সরাসরি store মেথডের মাধ্যমেও ফাইল স্টোর করা যায়।
কাস্টম নামেই স্টোর করতে storeAs() মেথড ব্যবহৃত হয়।
$path = $request->file('avatar')->storeAs('avatar/public', $request->user()->id); // ফাইলের নাম

ঐটি এভাবে আমরা শো করতে পারি:
photo.blade.php

ফাইল বা ফাইলের শুধু কন্টেন্ট নেওয়ার জন্য এবং PDF বা CSV পড়ার জন্য storage::get() মেথড ব্যবহৃত হয়।

return Storage::download('file.jpg');

Episode 3: file storage: Restricting file access (public files vs auth protected files)

আমরা যদি ইমফাইলের অ্যাক্সেস কন্ট্রোল করতে চাই, তা তো করতে পারি। storage>app>files এই ফোল্ডারের আমাদের ফাইল রাখব। যেহেতু এই ফোল্ডারের সাথে public ফোল্ডারের symlink করা নাই, তাই এই ফোল্ডারের ফাইলগুলো পাবলিকলি অ্যাক্সেসিবল নয়।

files > fundamental.php এই ফাইলটা তখন লেআউটগুলোর অপশন দেবে। আমরা শুধুমাএ অথেন্টিকেটেড ইউজারকে এই ফাইলের অ্যাক্সেস দেব।

```php
web.php
Route::get('/file', function (Request $request) {
    // Authorize
    return Storage::download('files/fundamentals.pdf');
})->middleware('auth');

এতে করে আরেকজন কোনো ইউজার ডাউনলোডের চেষ্টা করতে পারবে, যে owner কিনা, বা রোলটা কি সেটা চেক করবে দেবে।
```

অপরপক্ষে আমরা যদি public সরাসরি url দিয়ে অ্যাক্সেস করতে পারব। যেমন - সরাসরি url দিয়ে অ্যাক্সেস করতে পারব। public/images/1.jpg এই url দিয়ে অ্যাক্সেস করা যাবে। `localhost:8000/images/1.jpg` এই url দিয়ে অ্যাক্সেস করা যাবে।

File Storage: Episode 4: Scaling issue for file storage:

আমাদের অ্যাপ্লিকেশনটি সর্বদা একটা সার্ভারে নাও থাকতে পারে। ফাইল সাধারণত অ্যাপ্লিকেশন সার্ভারের মধ্যেই স্টোর হয়। আমাদের অনেক বেশি ট্রাফিক আসলে বেশি ইউজার হ্যান্ডেল করতে হলে মাল্টিপল অ্যাপ্লিকেশন সার্ভার ব্যবহার করতে হতে পারে। মাল্টিপল অ্যাপ্লিকেশন সার্ভার ব্যবহার করলে মাঝখানে একটি Load balancer থাকে। ক্লায়েন্টের কাছ থেকে Load balancer এর কাছে রিকোয়েস্ট আসবে এবং Load balancer সিদ্ধান্ত নেবে যে রিকোয়েস্টটি কোথায় যাবে।
যদি একটা অ্যাপ্লিকেশন সার্ভারে আমাদের ফাইল থাকে এবং আরেকটি সার্ভার থেকে সেটি অ্যাক্সেস করতে চাই তাহলে একটি 404 Not Found এরর দেবে।

আমরা অনেক সময় Docker, Kubernetes ব্যবহার করে আমাদের অ্যাপ্লিকেশনটা মেইনটেইন করি। সেক্ষেত্রে একটা অ্যাপ্লিকেশন সার্ভার থাকে না। প্রত্যেকটা অ্যাপ্লিকেশন ইন্সট্যান্স একটা কন্টেইনারে রান হয়।

প্রতিবার কোড ডিপ্লয় করলে পুরোনো কন্টেইনার ডিস্ট্রয় হয়ে নতুন কন্টেইনার তৈরি হয়। আমাদের প্রোডাকশানে Docker, kubernetes থাকলে আমরা অ্যাপ্লিকেশন সার্ভারে কোনো লোকাল ডাটা স্টোর করব না। সেক্ষেত্রে আমরা ফাইলের জন্য কোনো থার্ড পার্টি স্টোরেজ ব্যবহার করব। যেমন: Amazon S3।
আমরা চাইলে Google Cloud ও ব্যবহার করতে পারি ফাইল স্টোর করার জন্য। কিন্তু এর জন্য লারাভেলের ডিফল্ট কোনো Driver নাই। তবে spatie-র একটা প্যাকেজ আছে।
