# মডিউল ৮: ডাটাবেজ মাইগ্রেশন (Database Migrations)

> [!IMPORTANT]
> **★ ইন্টারভিউয়ের জন্য গুরুত্বপূর্ণ প্রশ্ন:** লারাভেলে ডাটাবেজ মাইগ্রেশন (Database Migration) কি এবং এটি কেন ও কীভাবে ব্যবহার করা হয় উদাহরণসহ লিখ

ঐতিহ্যগতভাবে ডেভলপাররা যখন লোকাল মেশিনে কোনো প্রজেক্ট তৈরি করেন, তখন ডাটাবেজে টেবিল তৈরির জন্য সরাসরি পিএইচপি-মাই-অ্যাডমিন (phpMyAdmin) বা রানিং SQL কোড ব্যবহার করতেন। এতে প্রজেক্টের কোড যখন অন্য ডেভেলপারের কাছে পাঠানো হতো বা লাইভ সার্ভারে ডেপ্লয় করা হতো, তখন ডাটাবেজের টেবিলগুলো নতুন করে তৈরি করা বেশ ঝামেলার হতো। 

এই সমস্যার সমাধান করতেই লারাভেলে এসেছে **Migrations**। মাইগ্রেশনকে ডাটাবেজের **Version Control** বলা যেতে পারে, যা আপনাকে পিএইচপি কোড ব্যবহার করে ডাটাবেজের টেবিল তৈরি, কলাম যুক্ত বা মডিফাই করার সুবিধা দেয়।

---

## ১. র এসকিউএল বনাম লারাভেল মাইগ্রেশন (Raw SQL vs Migrations) ★

### ক. র এসকিউএল (Raw SQL) টেবিল তৈরি করার কমান্ড:
```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### খ. লারাভেল মাইগ্রেশনে অবজেক্ট ওরিয়েন্টেড পদ্ধতিতে একই কাজ:
লারাভেলে আপনাকে সরাসরি কোনো SQL কুয়েরি লিখতে হবে না। এটি পিএইচপির অবজেক্ট ওরিয়েন্টেড উপায়ে চমৎকার ক্লাস সরবরাহ করে যা ইন্টারনালি কনভার্ট হয়ে ডাটাবেজের জন্য র এসকিউএল জেনারেট করে:
```php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('users', function (Blueprint $table) {
            $table->id(); // অটো-ইনক্রিমেন্টিং প্রাইমারি কি কলাম তৈরি করবে
            $table->string('name'); // VARCHAR(255) কলাম তৈরি করবে
            $table->string('email')->unique(); // ইউনিক কন্ডিশনসহ কলাম তৈরি করবে
            $table->timestamps(); // created_at এবং updated_at কলাম তৈরি করবে
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('users');
    }
};
```

## ২. মাইগ্রেশনের গুরুত্বপূর্ণ নিয়ম ও বেস্ট প্র্যাকটিস ★

> [!WARNING]
> **★ ইন্টারভিউয়ের জন্য গুরুত্বপূর্ণ প্রশ্ন:** আপনার প্রজেক্টের একটি মাইগ্রেশন ফাইল রান হওয়ার পর সেটি যদি অলরেডি প্রোডাকশন বা লাইভ সার্ভারে চলে যায়, তবে কি সেই ফাইলে কলামের পরিবর্তন বা এডিট করা যাবে?

**কখনোই না!**
যদি কোনো মাইগ্রেশন ফাইল একবার তৈরি হয়ে ডাটাবেজে রান হয়ে যায় (বিশেষ করে তা যদি লাইভ বা প্রোডাকশন সার্ভারে থাকে), তবে সেই ফাইলে গিয়ে ম্যানুয়ালি কোনো কোড এডিট বা চেঞ্জ করা যাবে না। 

### কারণ ও সমাধান:
- **সমস্যা:** আপনি যদি লোকালি ফাইল এডিট করে রান করেন, তবে লাইভ সার্ভারের ডাটাবেজ তা ট্র্যাক করতে পারবে না এবং প্রজেক্টের সাথে ডাটাবেজের সিঙ্ক নষ্ট হয়ে যাবে।
- **সমাধান:** ডাটাবেজে নতুন কোনো কলাম যোগ বা রিনেম করতে চাইলে সবসময় নতুন আরেকটি মাইগ্রেশন ফাইল তৈরি করতে হবে এবং সেখানে নতুন কলামের ডেফিনিশন লিখতে হবে:
  ```bash
  php artisan make:migration add_phone_to_users_table --table=users
  ```
  এটি প্রজেক্টের ট্র্যাক ও ইতিহাস সুন্দরভাবে বজায় রাখে।

## ৩. মাইগ্রেশন রান ট্র্যাকিং কীভাবে হয়?

লারাভেল কীভাবে বুঝতে পারে যে কোন কোন মাইগ্রেশন অলরেডি রান হয়েছে আর কোনগুলো এখনো হয়নি?

লারাভেল যখন প্রথমবার মাইগ্রেশন চালায়, তখন সে আপনার ডাটাবেজে স্বয়ংক্রিয়ভাবে **`migrations`** নামের একটি বিশেষ টেবিল তৈরি করে নেয়।
- আপনি যখনই `php artisan migrate` কমান্ড রান করেন, লারাভেল এই টেবিলটি চেক করে।
- যে ফাইলগুলোর এন্ট্রি এই টেবিলে ইতিমধ্যে রয়েছে, লারাভেল সেগুলোকে স্কিপ করে।
- যে ফাইলগুলো নতুন তৈরি হয়েছে এবং এই টেবিলে এন্ট্রি নেই, লারাভেল শুধুমাত্র সেই নতুন ফাইলগুলোকে এক্সিকিউট করে এবং এক্সিকিউশন সফল হলে এই টেবিলে একটি করে এন্ট্রি দিয়ে রাখে।

## ৪. গুরুত্বপূর্ণ মাইগ্রেশন কমান্ডসমূহ

- **নতুন মাইগ্রেশন ফাইল তৈরি করা:**
  ```bash
  php artisan make:migration create_products_table
  ```
- **মাইগ্রেশন ফাইলগুলো ডাটাবেজে রান করা:**
  ```bash
  php artisan migrate
  ```
- **পূর্বের সর্বশেষ মাইগ্রেশনটি ফেরত নেওয়া (Rollback):**
  ```bash
  php artisan migrate:rollback
  ```
- **সমস্ত মাইগ্রেশন ডিলিট করে নতুন করে রান করা (সাবধান! সমস্ত ডেটা ডিলিট হয়ে যাবে):**
  ```bash
  php artisan migrate:fresh
  ```
- **মাইগ্রেশনের বর্তমান স্ট্যাটাস দেখা (কোনটি রান হয়েছে, কোনটি বাকি):**
  ```bash
  php artisan migrate:status
  ```

## ৫. SQLite ডাটাবেজ সেটআপ ও ব্যবহার (SQLite Database Setup)

লোকাল ডেভেলপমেন্ট বা ছোট প্রজেক্টের জন্য MySQL সার্ভার সেটআপ করার ঝামেলা এড়াতে আমরা অত্যন্ত হালকা এবং সার্ভারলেস **SQLite** ডাটাবেজ ব্যবহার করতে পারি।

### ক. SQLite ফাইল তৈরি করা:
প্রজেক্টের রুট ডিরেক্টরি থেকে `database` ফোল্ডারের ভেতরে **`database.sqlite`** নামে একটি ফাঁকা ফাইল তৈরি করে নিন:
```
database/database.sqlite
```

### খ. `.env` ফাইল কনফিগার করা:
SQLite ডাটাবেজ ব্যবহার করার জন্য আমাদের `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` এই ক্রেডেনশিয়ালগুলোর কোনো প্রয়োজন নেই। শুধু নিচের মতো করে সংযোগ বা কানেকশন টাইপ সেট করে দিলেই হবে:
```ini
DB_CONNECTION=sqlite
```
*(লারাভেল স্বয়ংক্রিয়ভাবে `database/database.sqlite` ফাইলটিকে ডাটাবেজ হিসেবে রিড করে নেবে।)*

### গ. ভিজ্যুয়াল ট্র্যাকিং:
ভিএস কোডে ডাটাবেজের টেবিলগুলো সরাসরি দেখার জন্য **SQLite** অথবা **SQLite Viewer** এক্সটেনশনটি ইনস্টল করে নিতে পারেন।

## ৬. মাইগ্রেশন রোলব্যাক ও পরিবর্তন (Rollback, Reset, Fresh & Refresh)

মাইগ্রেশনে কোনো কলামের নাম বা ডাটা টাইপ ভুল হলে, আমরা নিচের কমান্ডগুলোর সাহায্য নিয়ে ডাটাবেজ রিসেট বা রোলব্যাক করতে পারি:

### ক. সর্বশেষ মাইগ্রেশন রোলব্যাক করা:
পূর্ববর্তী ধাপে চালানো সর্বশেষ মাইগ্রেশন ব্যাচটি বাতিল করতে:
```bash
php artisan migrate:rollback
```
যেমন: আমরা যদি কোনো টেবিলে নতুন কলাম `isAdmin` যোগ করতে চাই:
```php
$table->boolean('isAdmin')->default(false);
```
মাইগ্রেশন রান করার পর ভুল ধরা পড়লে আমরা `migrate:rollback` করে ফাইলটি এডিট করে পুনরায় `php artisan migrate` রান করতে পারবো।

### খ. সমস্ত মাইগ্রেশন রোলব্যাক করা (Reset):
ডাটাবেজের সমস্ত টেবিলের মাইগ্রেশন একসাথে রোলব্যাক করতে:
```bash
php artisan migrate:reset
```

### গ. সমস্ত টেবিল ড্রপ করে নতুন করে মাইগ্রেশন চালানো (Fresh):
ডাটাবেজের সব টেবিল ডিলিট (Drop) করে একদম নতুন করে সব মাইগ্রেশন রান করতে:
```bash
php artisan migrate:fresh
```

### ঘ. রোলব্যাক করে পুনরায় মাইগ্রেশন চালানো (Refresh):
ডাটাবেজের সমস্ত টেবিল রোলব্যাক বা ডাউন করে পুনরায় নতুন করে মাইগ্রেশন চালাতে:
```bash
php artisan migrate:refresh
```

> [!NOTE]
> **Fresh এবং Refresh কমান্ডের মধ্যে পার্থক্য:**
> - `migrate:fresh` কমান্ডটি ডাটাবেজের সমস্ত টেবিলকে সরাসরি ড্রপ (Drop) করে দেয়; এটি মাইগ্রেশন ফাইলের `down()` মেথড কল করে না।
> - `migrate:refresh` কমান্ডটি প্রতিটি মাইগ্রেশন ফাইলের `down()` মেথড এক এক করে কল করে রোলব্যাক সম্পন্ন করে এবং এরপর আবার `up()` মেথড রান করে।

## ৭. রানিং ডাটাবেজে নতুন কলাম যুক্ত করা (Adding Columns to Existing Table)

ইতিমধ্যে তৈরি হওয়া কোনো টেবিলে নতুন কলাম যোগ করতে চাইলে নতুন একটি মাইগ্রেশন ফাইল তৈরি করতে হবে:

```bash
php artisan make:migration add_post_id_column_to_comments_table
```
*(মাইগ্রেশনের নাম দেওয়ার সময় স্পেসের পরিবর্তে আন্ডারস্কোর `_` ব্যবহার করা উত্তম।)*

### ক. মাইগ্রেশন ফাইলে কলাম ডিফাইন করা:
```php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::table('comments', function (Blueprint $table) {
            // foreignId যুক্ত করা হলো যা comments টেবিলের সাথে posts টেবিলকে রিলেট করবে
            $table->foreignId('post_id')->constrained();
        });
    }

    public function down(): void
    {
        Schema::table('comments', function (Blueprint $table) {
            // রোলব্যাক করার সময় কলামটি ড্রপ করা হবে
            $table->dropColumn('post_id');
        });
    }
};
```
*(এখানে `constrained()` মেথড ব্যবহার করায় লারাভেল অটোমেটিক্যালি এটিকে `users` বা সংশ্লিষ্ট টেবিলের `id` কলামের সাথে ম্যাপ করে নেবে।)*

### খ. নির্দিষ্ট কলামের পরে যুক্ত করা (Column Modifiers):
আমরা চাইলে কোনো নির্দিষ্ট কলামের পর নতুন কলামটি বসাতে পারি (যেমন: `is_admin` কলামের পরে):
```php
$table->foreignId('post_id')->after('is_admin')->constrained();
```
> [!WARNING]
> কলাম সাজানোর এই `after()` মেডিফায়ারটি শুধুমাত্র **MySQL** এবং **PostgreSQL** ডাটাবেজের ক্ষেত্রে কাজ করে; **SQLite** ডাটাবেজে এটি সাপোর্ট করে না।
