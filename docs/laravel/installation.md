# মডিউল ৮: লারাভেল ইনস্টলেশন ও সেল (Installation & Laravel Sail)

> [!IMPORTANT]
> **★ ইন্টারভিউয়ের জন্য গুরুত্বপূর্ণ প্রশ্ন:** লারাভেল কীভাবে ইনস্টল করতে হয় এবং লারাভেল সেল (Laravel Sail) কি ও এর কাজ উদাহরণসহ লিখ

লারাভেল প্রজেক্ট লোকাল মেশিনে ইনস্টল এবং সেটআপ করার একাধিক চমৎকার উপায় রয়েছে। এই চ্যাপ্টারে আমরা কম্পোজার দিয়ে লারাভেল ইনস্টলেশনের মৌলিক বিষয়সমূহ এবং ডকার-ভিত্তিক লোকাল ডেভেলপমেন্ট এনভায়রনমেন্ট **Laravel Sail** নিয়ে বিস্তারিত আলোচনা করব।

---

## ১. লারাভেল ইনস্টলেশন বেসিকস (Laravel Installation Basics)

লোকাল মেশিনে পিএইচপির ডিপেন্ডেন্সি ম্যানেজার **Composer** ব্যবহার করে খুব সহজেই নতুন লারাভেল প্রজেক্ট ইনস্টল করা যায়।

### ক. লারাভেল প্রজেক্ট তৈরির কমান্ড
আপনার টার্মিনালে নিচের কমান্ডটি রান করে একটি ফ্রেশ লারাভেল প্রজেক্ট ইনস্টল করতে পারেন:
```bash
composer create-project laravel/laravel laravel-career-path-project
```
এই কমান্ডটি রান করলে লারাভেলের সর্বশেষ স্থিতিশীল ভার্সনের একটি প্রজেক্ট `laravel-career-path-project` ফোল্ডারে ইনস্টল হয়ে যাবে।

---

## ২. কম্পোজার কমান্ডের গুরুত্বপূর্ণ পার্থক্য ★

> [!IMPORTANT]
> **★ ইন্টারভিউয়ের জন্য গুরুত্বপূর্ণ প্রশ্ন:** `composer require` এবং `composer update` এর মধ্যে পার্থক্য কী? এবং `laravel/laravel` ও `laravel/framework` এর সম্পর্ক কী?

### ১. `composer require` বনাম `composer update`
- **`composer require`:** প্রজেক্টে একদম নতুন কোনো থার্ড-পার্টি প্যাকেজ বা লাইব্রেরি ইনস্টল করতে এটি ব্যবহৃত হয়। (যেমন: `composer require laravel/breeze --dev`)। এটি প্যাকেজটি ডাউনলোড করে এবং স্বয়ংক্রিয়ভাবে `composer.json` ও `composer.lock` ফাইল আপডেট করে।
- **`composer update`:** আপনার প্রজেক্টের `composer.json` ফাইলে ইতিমধ্যে থাকা (Existing) প্যাকেজগুলোর সর্বশেষ ভার্সন চেক করে সেগুলোকে আপডেট করতে এটি ব্যবহৃত হয়।

### ২. `laravel/laravel` বনাম `laravel/framework`
- **`laravel/laravel` (The Skeleton):** এটি হলো লারাভেলের প্রজেক্ট স্ট্রাকচার বা মূল কঙ্কাল (Skeleton Repository)। আপনি যখন `create-project` কমান্ড দেন, তখন গিটহাবের এই রিপোজিটরি থেকে ডিরেক্টরি এবং কনফিগারেশন ফাইলগুলো ডাউনলোড হয়। এর কোড আপনি আপনার প্রজেক্টে ইচ্ছামতো পরিবর্তন করতে পারেন।
- **`laravel/framework` (The Engine):** এটি হলো লারাভেলের আসল ইঞ্জিন বা কোর ফ্রেমওয়ার্ক। লারাভেলের সমস্ত ইন্টারনাল লজিক, রাউটার, অবজেক্ট কন্টেইনার এবং সার্ভিসগুলো এর মধ্যে থাকে। এটি `vendor/laravel/framework` ডিরেক্টরিতে ডাউনলোড হয়। **এই ফোল্ডারের কোনো কোড কখনো ম্যানুয়ালি পরিবর্তন করা যাবে না**, কারণ পরবর্তী সময়ে কম্পোজার আপডেট দিলে আপনার সব পরিবর্তন মুছে যাবে।

## ৩. লারাভেল সেল পরিচিতি (Intro to Laravel Sail)

আপনি যদি আপনার লোকাল কম্পিউটারে পিএইচপি, মাইএসকিউএল, নোড বা অন্যান্য কোনো ডাটাবেজ টুলস ইনস্টল না করেই একটি সম্পূর্ণ লারাভেল প্রজেক্ট রান করতে চান, তবে **Laravel Sail** আপনার জন্য সবচেয়ে সেরা সমাধান।

**Laravel Sail** হলো ডকার (Docker) কনটেইনার ব্যবহার করে লারাভেল ডেভেলপমেন্ট চালানোর জন্য একটি চমৎকার ও লাইটওয়েট কমান্ড-লাইন ইন্টারফেস (CLI)।

### ক. নতুন প্রজেক্টে Sail সেটআপ করা
নতুন লারাভেল প্রজেক্ট ইনস্টল করার সময় আপনি নিচের মতো করে সরাসরি সেল-সহ প্রজেক্ট নামাতে পারেন:
```bash
curl -s "https://laravel.build/example-app" | bash
```

### খ. এক্সিস্টিং (Existing) প্রজেক্টে Sail ইনস্টল করার কমান্ড
আপনার যদি ইতিমধ্যে কোনো প্রজেক্ট তৈরি করা থাকে এবং সেখানে সেল সেটআপ করতে চান, তবে টার্মিনালে নিচের কমান্ডগুলো রান করুন:
```bash
# ১. সেল প্যাকেজ ডেভেলপমেন্ট ডিপেন্ডেন্সি হিসেবে ইনস্টল করুন
composer require laravel/sail --dev

# ২. সেলের কনফিগারেশন ইনস্টল করুন
php artisan sail:install
```
কমান্ডটি রান করার পর আপনাকে জিজ্ঞেস করা হবে আপনি কোন কোন ডাটাবেজ বা সার্ভিস ব্যবহার করতে চান (যেমন: `mysql`, `redis`, `mailpit` ইত্যাদি)। পছন্দমতো সার্ভিসগুলো সিলেক্ট করলে এটি একটি `docker-compose.yml` ফাইল তৈরি করে দেবে।

## ৪. সেলের ব্যবহার ও কমান্ডসমূহ

লোকাল সেলের সব এক্সিকিউটেবল ফাইল থাকে `vendor/bin/sail` ফোল্ডারের ভেতর।

### ক. সেল কনটেইনার আপ ও ডাউন করা
ডকার কনটেইনার চালু করার জন্য টার্মিনালে লিখুন:
```bash
./vendor/bin/sail up
```
*টিপস: কনটেইনারগুলো ব্যাকগ্রাউন্ডে (Detached Mode) রান করতে `-d` ফ্ল্যাগ ব্যবহার করুন:*
```bash
./vendor/bin/sail up -d
```
কাজ শেষ হয়ে গেলে সিস্টেমের রিসোর্স বা কম্পিউটারের র্যাম বাঁচাতে কনটেইনারগুলো বন্ধ করে নেওয়া ভালো:
```bash
./vendor/bin/sail down
```

### খ. সেলের জন্য শর্টকাট (Alias) সেটআপ করা
বারবার `./vendor/bin/sail` লেখা কিছুটা ঝামেলার। তাই আপনার টার্মিনালে (যেমন Git Bash, Zsh বা Bash shell) একটি Alias বা শর্টকাট সেটআপ করে নিতে পারেন:
```bash
alias sail='[ -f sail ] && sh sail || sh vendor/bin/sail'
```
এই শর্টকাটটি সেট করার পর আপনি সরাসরি শুধুমাত্র `sail up -d` বা `sail down` কমান্ডগুলো রান করতে পারবেন।

### গ. আর্টিসান ও কিউ রান করা সেলে
যেহেতু আপনার পিসির পিএইচপি এখন ডকার কনটেইনারের ভেতরে রান হচ্ছে, তাই পিএইচপি এবং আর্টিসান কমান্ড চালানোর জন্য সেলের মাধ্যমে কল করতে হবে:

| লোকাল কমান্ড (উইদাউট সেল) | সেলের কমান্ড (কনটেইনারের ভেতরে) |
| :--- | :--- |
| `php artisan serve` | `sail up` (স্বয়ংক্রিয়ভাবে পোর্ট ৮০ বা ৮০০০ এ রান হবে) |
| `php artisan migrate` | `sail artisan migrate` |
| `php artisan queue:work` | `sail artisan queue:work` |
| `composer install` | `sail composer install` |

### ঘ. কনটেইনারের ভেতরে ডিরেক্ট সেল অ্যাক্সেস
আপনি যদি কনটেইনারের ভেতরে সরাসরি ঢুকে পিএইচপি বা ব্যাশ কমান্ড চালাতে চান:
```bash
# সাধারণ ইউজার হিসেবে টার্মিনাল অ্যাক্সেস
sail shell

# রুট (Root) ইউজার হিসেবে টার্মিনাল অ্যাক্সেস
sail root-shell
```

### ঙ. বিভিন্ন পিএইচপি ভার্সন ব্যবহার করা
সেলের সাহায্যে আপনি খুব সহজেই পিএইচপির যেকোনো নির্দিষ্ট ভার্সন (যেমন পিএইচপি ৮.২ বা ৮.৩) দিয়ে প্রজেক্ট রান করতে পারেন। এর কনফিগারেশন রানটাইমগুলো `vendor/laravel/sail/runtimes/` ফোল্ডারে সংরক্ষিত থাকে এবং আপনি `docker-compose.yml` এর `context` পরিবর্তন করে সহজেই ভার্সন পরিবর্তন করতে পারবেন।
```bash
# রানিং কনটেইনারগুলোর বর্তমান অবস্থা দেখতে
sail ps
```
