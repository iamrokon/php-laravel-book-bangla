# মডিউল ১০ ও ১১: অথেন্টিকেশন ও মিডলওয়্যার (Authentication & Middleware in Laravel)

একটি আধুনিক ওয়েব অ্যাপ্লিকেশনের সবচেয়ে গুরুত্বপূর্ণ অংশগুলোর একটি হলো নিরাপত্তা ও অথেন্টিকেশন (Authentication)। এই মডিউলে আমরা লারাভেলের স্বয়ংক্রিয় অথেন্টিকেশন সিস্টেম (Starter Kits), সেশন বনাম টোকেন বেসড অথেন্টিকেশন, JWT, লারাভেল স্যাঙ্কটাম (Sanctum), পাসপোর্ট (Passport), ওঅথ ২.০ (OAuth 2.0), পাসওয়ার্ড রিসেট এবং ইমেইল ভেরিফিকেশন ফ্লো নিয়ে আলোচনা করব।

## ১. লারাভেল অথেন্টিকেশন ও স্টার্টার কিটস (Laravel Starter Kits)

লারাভেলে অথেন্টিকেশন সিস্টেম স্ক্র্যাচ থেকে তৈরি করতে হয় না। ডেভেলপমেন্ট দ্রুত করার জন্য লারাভেল অফিশিয়াল দুটি স্টার্টার কিট (Starter Kits) প্রদান করে থাকে:
1. **Laravel Breeze:** খুব সিম্পল ও ক্লিন টেইলউইন্ড সিএসএস বেসড স্টার্টার কিট। ব্লেড, রিয়্যাক্ট বা ভিউ দিয়ে এটি সেটআপ করা যায়।
2. **Laravel Jetstream:** একটু অ্যাডভান্সড স্টার্টার কিট যা টু-ফ্যাক্টর অথেন্টিকেশন (2FA), টিম ম্যানেজমেন্ট ও এপিআই টোকেন সাপোর্ট দেয়।

### স্টার্টার কিটে ডিফল্ট যেসব ফিচার থাকে:
- **Registration & Login** (নিবন্ধন ও প্রবেশ)
- **Forget Password & Reset Password** (পাসওয়ার্ড ভুলে গেলে পুনরুদ্ধার)
- **Remember Me** (লগইন তথ্য মনে রাখা)
- **Logout** (লগআউট করা)
- **Email Verification** (ইমেইল যাচাইকরণ)
- **2FA (Two-Factor Authentication)** (দ্বি-স্তরের নিরাপত্তা)
- **Phone Verification / SMS OTP** (মোবাইল ওয়ান-টাইম পাসওয়ার্ড)
- **Social Login (Social Auth)** (গুগল বা ফেসবুকের মাধ্যমে লগইন)

## ২. সেশন বনাম টোকেন বেসড অথেন্টিকেশন (Stateful vs Stateless Auth)

অথেন্টিকেশন মূলত দুই ভাগে বিভক্ত:

### ক. সেশন বেসড অথেন্টিকেশন (Stateful Auth):
ইউজার একবার লগইন করলে তার ব্রাউজার কুকি (Cookie) এর মাধ্যমে সেশন আইডি পাঠিয়ে দেয়। সার্ভার সেশন আইডির সাথে লোকাল সেশন ম্যাচ করে ইউজার চিনে নেয়। এটি সাধারণত ওয়েব ব্রাউজারের ক্ষেত্রে ব্যবহূত হয়।

### খ. টোকেন বেসড অথেন্টিকেশন (Stateless Auth):
মোবাইল অ্যাপ বা থার্ড-পার্টি সার্ভিসগুলোর রিকোয়েস্টে সাধারণত কুকি থাকে না। তাই কুকি ছাড়া ইউজার শনাক্ত করতে প্রতিটি রিকোয়েস্টের হেডারে একটি ইউনিক টোকেন পাঠানো হয়।
```
মোবাইল/ক্লায়েন্ট ───(১. লগইন রিকোয়েস্ট)───► সার্ভার
মোবাইল/ক্লায়েন্ট ◄───(২. রেসপন্স ডাটা + টোকেন)─── সার্ভার
মোবাইল/ক্লায়েন্ট ───(৩. পরবর্তী রিকোয়েস্ট + টোকেন)───► সার্ভার
```

## ৩. জেডব্লিউটি (JWT - JSON Web Token) এবং এর গঠন

JWT একটি সম্পূর্ণ **Stateless Token**। অর্থাৎ সার্ভারের ডেটাবেজে এই টোকেনটি সেভ না রেখেও সরাসরি ডিকোড করে ইউজার চেনা সম্ভব।

JWT টোকেন মূলত ৩টি অংশ নিয়ে গঠিত যা ডট `.` দিয়ে যুক্ত থাকে:
1. **Header:** টোকেনটি কোন অ্যালগরিদম (যেমন: HS256) দিয়ে তৈরি তা লেখা থাকে।
2. **Payload:** টোকেনের মূল ডেটা (যেমন: ইউজারের আইডি, নাম, টোকেন মেয়াদোত্তীর্ণের সময় ইত্যাদি) এখানে থাকে।
3. **Signature:** সিক্রেট কি (Secret Key) ব্যবহার করে জেনারেট করা ডিজিটাল স্বাক্ষর যা টোকেনটি পরিবর্তন করা হয়েছে কিনা তা ভেরিফাই করে।

```
Encoded JWT: eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0NTYifQ.signature_key
             └──── Header ────┘ └──── Payload ───┘ └─── Signature ──┘
```

> [!WARNING]
> **JWT এর একটি বড় অসুবিধা:** যেহেতু JWT ডেটাবেজে সেভ থাকে না, তাই কোনো ইউজারের মোবাইল বা টোকেন চুরি হলে ডেটাবেজ থেকে তাৎক্ষণিকভাবে সেই নির্দিষ্ট টোকেনটিকে ইনভ্যালিড (Invalid) বা ব্লক করা বেশ কঠিন। এটি করতে গেলে ব্ল্যাকলিস্ট (Blacklist) ডাটাবেজ ব্যবহার করতে হয়, যা করতে গেলে টোকেনটি আবার Stateful হয়ে যায়।

## ৪. লারাভেল স্যাঙ্কটাম (Laravel Sanctum) ★

**Laravel Sanctum** লারাভেলের অফিশিয়াল লাইটওয়েট টোকেন ও সেশন বেসড অথেন্টিকেশন প্যাকেজ। এটি কোনো JWT ব্যবহার করে না।

### স্যাঙ্কটামের মূল সুবিধাসমূহ:
1. **SPA Authentication:** সিঙ্গেল পেজ অ্যাপ্লিকেশন (যেমন: React, Vue, Next.js) এর জন্য কুকি ও সেশন বেসড অথেন্টিকেশন সুবিধা দেয়।
2. **API Token Authentication:** মোবাইল অ্যাপ বা এপিআই ক্লায়েন্টের জন্য টোকেন ভিত্তিক অথেন্টিকেশন। স্যাঙ্কটাম এই টোকেনগুলো ডাটাবেজের `personal_access_tokens` টেবিলে স্টোর করে রাখে। তাই খুব সহজেই সার্ভার থেকে যেকোনো অ্যাক্টিভ টোকেন ডিলিট বা ইনভ্যালিড করে দেওয়া যায় (Blacklist এর প্রয়োজন হয় না)।

### টোকেন তৈরি ও পারমিশন/অ্যাবিলিটি সেটআপ:
স্যাঙ্কটামে টোকেন জেনারেট করার সময় নির্দিষ্ট কাজের পারমিশন বেঁধে দেওয়া যায়:
```php
// 'server:update' পারমিশন দিয়ে টোকেন তৈরি
$token = $user->createToken('token-name', ['server:update'])->plainTextToken;
```
ইউজার রিকোয়েস্টে এই পারমিশন আছে কিনা তা চেক করার উপায়:
```php
if ($user->tokenCan('server:update')) {
    // অ্যাকশন করার অনুমতি আছে
}
```

### মিডলওয়্যার লেভেলে অ্যাবিলিটি চেক করা:
```php
Route::get('/orders', function() {
    // লজিক...
})->middleware(['auth:sanctum', 'abilities:check-status,place-orders']);
```

## ৫. ফায়ারওয়াল, কর্স ও ওঅথ ২.০ (Firewall, CORS & OAuth 2.0)

### ক. CORS (Cross-Origin Resource Sharing):
একটি নির্দিষ্ট ডোমেইন ব্যতীত অন্য ডোমেইন থেকে রিকোয়েস্ট আসলে ব্রাউজার সিকিউরিটির জন্য ডাটা ব্লক করে দেয়। এটি এনাবল করার জন্য লারাভেলে CORS কনফিগার করতে হয়। ফায়ারওয়াল অ্যাপ্লিকেশন পর্যন্ত আসার পূর্বেই ডিরেক্ট অ্যাটাক থেকে সার্ভারকে রক্ষা করে।

### খ. OAuth 2.0 মেকানিজম:
যদি কোনো থার্ড-পার্টি অ্যাপ্লিকেশন (যেমন: PrintMagic) ইউজারের অনুমতি নিয়ে কোনো সার্ভিস (যেমন: Google Drive) থেকে তার ডেটা অ্যাক্সেস করতে চায়, তবে ইউজারকে পাসওয়ার্ড শেয়ার না করেই নির্দিষ্ট মেয়াদের টোকেন দেওয়ার মেকানিজমই হলো **OAuth 2.0**।

```
User ───► PrintMagic (Third-party)
             │
             ▼ (১. এক্সেস রিকোয়েস্ট)
Google Drive (OAuth Server) ───► ইউজার পারমিশন চাবে (Request Approved)
             │
             ▼ (২. Authorization Code পাবে)
PrintMagic ───► Google Drive (ClientId + Secret দিয়ে Access Token পাবে)
```
লারাভেলে ওঅথ ২.০ প্রোটোকলের কমপ্লিট ইমপ্লিমেন্টেশন করতে **Laravel Passport** প্যাকেজ ব্যবহার করা হয়। আর গুগল, ফেসবুক, গিটহাব দিয়ে সহজে সোশ্যাল লগইন করতে লারাভেলের অফিশিয়াল **Laravel Socialite** প্যাকেজ ব্যবহার করা হয়।

### গ. এসএসও (SSO - Single Sign On):
SSO হলো এমন এক অথেন্টিকেশন মেকানিজম যেখানে ইউজার একবার মাত্র সাইন-ইন করে একই কোম্পানির বিভিন্ন সার্ভিস (যেমন: Google-এ লগইন করলে Drive, YouTube, Gmail এও অটোমেটিক লগইন হয়ে যাওয়া) ব্যবহার করতে পারে। এর জন্য SAML, OAuth, OIDC প্রোটোকল ব্যবহৃত হয়।

## ৬. পাসওয়ার্ড রিসেট ফ্লো (Password Reset Workflow)

ইউজার পাসওয়ার্ড ভুলে গেলে কিভাবে সম্পূর্ণ মেকানিজম কাজ করে:
1. প্রথমে ইউজার তার ইমেইল ইনপুট দিয়ে সাবমিট করে।
2. অ্যাপ্লিকেশন ডেটাবেজে উক্ত ইমেইলের কোনো ইউজার আছে কিনা যাচাই করে।
3. ইউজার থাকলে একটি ইউনিক পাসওয়ার্ড রিসেট লিংক তৈরি করে এবং সেই টোকেনটি ডাটাবেজের `password_reset_tokens` টেবিলে উক্ত ইমেইলের বিপরীতে সেভ করে।
4. ইউজারের ইমেইলে উক্ত টোকেন সহকারে একটি রিসেট লিংক ইমেইলে পাঠানো হয়।
5. ইউজার ইমেইলে লিংকে ক্লিক করলে ব্রাউজার লিংক থেকে টোকেনটি রিড করে ভ্যালিডেট করে এবং ইউজারকে নতুন পাসওয়ার্ড সেট করতে দেয়।

> [!NOTE]
> লোকাল ডেভেলপমেন্টে মেইল টেস্ট করার জন্য লারাভেলে চমৎকার একটি টুল ব্যবহার করা হয় যার নাম **Mailpit**। এটি লোকাল মেইল সার্ভার হিসেবে কাজ করে এবং ব্রাউজারে ইনবক্স দেখার সুবিধা দেয়।

## ৭. ইমেইল ভেরিফিকেশন ফ্লো (Email Verification Workflow)

রেজিস্ট্রেশনের সময় স্প্যাম বা ভুয়া মেইল ঠেকাতে ইমেইল যাচাইকরণ অত্যন্ত জরুরি।

### ক. মাইগ্রেশন টেবিল ট্রাক:
`users` টেবিলে `email_verified_at` নামে একটি কলাম থাকে। যতক্ষণ ইউজার মেইল ভেরিফাই না করবে, কলামটি `null` থাকে।

### খ. ভেরিফিকেশন কন্ট্রোলার অ্যাকশন:
ইউজার মেইলের ভেরিফিকেশন লিংকে ক্লিক করলে `VerifyEmailController` এর `__invoke` মেথডটি রান হয়:
```php
namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use Illuminate\Foundation\Auth\EmailVerificationRequest;

class VerifyEmailController extends Controller
{
    public function __invoke(EmailVerificationRequest $request)
    {
        if ($request->user()->hasVerifiedEmail()) {
            return redirect()->intended('/dashboard?verified=1');
        }

        // ইমেইলটি ভেরিফাইড হিসেবে আপডেট করে দেয়
        if ($request->user()->markEmailAsVerified()) {
            // event(new Verified($request->user()));
        }

        return redirect()->intended('/dashboard?verified=1');
    }
}
```

## ৮. পাসওয়ার্ড কনফার্মেশন ও রেজিস্ট্রেশন ভ্যালিডেশন রুলস

### ক. পাসওয়ার্ড কনফার্মেশন রুট (`confirm-password`):
কোনো সেন্সিটিভ অ্যাকশন করার পূর্বে (যেমন ইউজার অ্যাকাউন্ট ডিলিট করা) নিরাপত্তা আরও জোরদার করতে অতিরিক্ত একটি স্টেপ হিসেবে ইউজারের বর্তমান পাসওয়ার্ড আরেকবার ইনপুট নিয়ে যাচাই করতে লারাভেলে পাসওয়ার্ড কনফার্ম মিডলওয়্যার ব্যবহার করা হয়।

### খ. রেজিস্ট্রেশন ফর্ম রিকোয়েস্ট ভ্যালিডেশন রুলস:
লারাভেল ব্রিজে রেজিস্ট্রেশনের জন্য স্ট্যান্ডার্ড `Rules\Password` সহ ভ্যালিডেশন রুলসের উদাহরণ:
```php
use Illuminate\Validation\Rules;

public function rules(): array
{
    return [
        'name' => ['required', 'string', 'max:255'],
        'email' => ['required', 'string', 'email', 'max:255', 'unique:users,email'],
        'password' => ['required', 'confirmed', Rules\Password::defaults()],
        'is_seller' => ['required', 'boolean'],
        // যদি সেলার হয়, তবে ক্যাটাগরি ও লোকেশন আবশ্যক
        'categories' => ['required_if:is_seller,1', 'array', 'min:1'],
        'locations' => ['required_if:is_seller,1', 'array', 'min:1'],
        'phone' => ['required', 'string'],
        'present_address' => ['required', 'string']
    ];
}
```
*(এখানে `required_if` ব্যবহার করে কন্ডিশনাল রুলস চমৎকারভাবে ডিক্লেয়ার করা হয়েছে)।*
